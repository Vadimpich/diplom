# Milestone v1.3: Admin UI Simplification

**Status:** ⚡ ARCHIVED WITH TECH DEBT 2026-03-25
**Phases:** 16-19
**Total Plans:** 4

## Overview

Milestone `v1.3` structurally simplified the admin panel without adding new admin capabilities. The admin contour was rebuilt as a quiet internal tool based on registries, filters, forms, and short read-only status surfaces instead of dashboards, descriptive panels, and summary-heavy layouts.

## Phases

### Phase 16: Admin Shell And Home Simplification

**Goal**: Администратор входит в тихий рабочий контур без dashboard-экрана, explanatory copy и декоративных блоков.
**Depends on**: Phase 15
**Plans**: 1 plan

Plans:

- [x] 16-01: Simplify the admin shell chrome and remove the admin dashboard layer

**Details:**
- Admin shell keeps the existing information architecture but removes descriptive sublabels, fixes the sidebar to viewport height, and pins logout to the bottom.
- `/admin` no longer behaves like a dashboard with cards and summaries; it becomes either a redirect or a minimal navigation or action surface.
- Across the shell and home entry no block remains that does not directly support navigation or a concrete admin action.

### Phase 17: Admin Registries As Tables

**Goal**: Пользователи и опросники читаются и управляются через плотные реестры, а не через карточные списки и summary-виджеты.
**Depends on**: Phase 16
**Plans**: 1 plan

Plans:

- [x] 17-01: Rebuild admin users and questionnaires into compact table-first registries

**Details:**
- Users screen is a compact table with inline filters and only operational columns such as login, role, status, and last login.
- Questionnaires screen is a compact table with name, question count, publication status, and updated timestamp, without usage metrics or decorative metadata blocks.
- Both registries open detail and edit flows by clicking the row, not by separate `Открыть` buttons.

### Phase 18: Admin Audit And Monitoring Reduction

**Goal**: Аудит и мониторинг превращаются в простые operational read-surfaces без dashboard-паттернов и developer-facing объяснений.
**Depends on**: Phase 17
**Plans**: 1 plan

Plans:

- [x] 18-01: Reduce admin audit and monitoring to plain operational status surfaces

**Details:**
- Audit screen is a plain log table with filters and expandable rows, without cards, summaries, or multi-block information architecture.
- Monitoring screen is reduced to a simple status list or table of services and states, without developer-observability prose or large widgets.
- Both screens feel like quiet read tools, not dashboards.

### Phase 19: Admin Edit Surfaces Minimalism

**Goal**: Редактирование административных сущностей выполняется в одном столбце через короткие формы и список действий, без summary-sidebars и технического текста.
**Depends on**: Phase 18
**Plans**: 1 plan

Plans:

- [x] 19-01: Simplify admin edit surfaces into single-column forms and ordered lists

**Details:**
- User detail and edit screen is a compact administrative form without technical notes or oversized secondary blocks.
- Questionnaire editor is single-column, keeps only the fields and ordered list of questions, and manages question order via drag-and-drop instead of noisy per-row controls and side panels.
- Settings screen is a simple vertical form without developer-facing descriptions or additional side panels.
