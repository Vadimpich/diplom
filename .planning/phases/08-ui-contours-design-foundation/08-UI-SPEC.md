## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline badge padding, skeleton offsets |
| sm | 8px | Compact control spacing, field hint gaps, stacked nav micro-spacing |
| md | 16px | Default control padding, card body spacing, form rows |
| lg | 24px | Section padding, page-header bottom rhythm, sidebar group gaps |
| xl | 32px | Shell gutters, page section separation, major card padding |
| 2xl | 48px | Major section breaks inside dashboards and overview pages |
| 3xl | 64px | Page-level top/bottom spacing for desktop shells |

Exceptions: 44px minimum touch target for icon-only controls; 40px remains the default button height for text buttons; source: default chosen within Phase 8 discretion.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.4 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.15 |

Typography rules:
- Use only weights `400` and `600`.
- Page descriptions, helper text, and secondary metadata use Body size with muted color, not a smaller custom scale.
- Operator contour uses the same type scale with tighter vertical composition, not different font sizes.
- Admin contour may use more Heading rows and section labels, but not additional type sizes.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F4F7FB` | App background, content canvas, neutral page surfaces |
| Secondary (30%) | `#243447` | Sidebar shell, emphasized navigation surfaces, contour identity blocks, inverse cards on dark surfaces |
| Accent (10%) | `#D7F0FD` | Active nav pill fill, selected-row fill, focus ring halo, informational badge backgrounds, skeleton shimmer tint |
| Destructive | `#DD2C2C` | Destructive actions only |

Accent reserved for: active navigation state, keyboard focus treatment, selected rows/cards, informational status badges, non-error toast accent, and skeleton highlight. Never use accent as the default fill for every button or link.

Semantic state color contract:
- Success: use green aligned with current token family for completed or healthy states.
- Warning: use yellow aligned with current token family for pending, degraded, or attention-needed states.
- Danger: use red aligned with destructive token for failed, blocked, or irreversible actions.
- Do not invent contour-specific status palettes; both operator and admin reuse one shared semantic mapping. Source: `08-CONTEXT.md` D-07.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Открыть рабочее место` |
| Empty state heading | `Здесь пока нет данных` |
| Empty state body | `Элементы появятся после первого действия в этом разделе. Проверьте фильтры или начните создание из основного сценария.` |
| Error state | `Не удалось загрузить данные. Обновите страницу. Если ошибка повторяется, проверьте доступность backend через readiness и повторите попытку.` |
| Destructive confirmation | `Выход из системы`: `Выйти из сеанса сейчас? Несохранённые локальные изменения будут потеряны.` |

Copy rules for Phase 8:
- Operator copy stays task-first, short, and operational.
- Admin copy stays explicit, calm, and explanatory without operator workflow wording.
- Loading states should prefer skeletons with a short nearby label only when the wait exceeds the immediate context.
- Avoid raw contract/status wording in user-facing labels unless the term is already part of the operator workflow.

## Phase-Specific Interaction Contract

- Keep a shared left-sidebar shell in both contours. Source: `08-CONTEXT.md` D-11.
- Operator sidebar must stay short and action-oriented with direct access to dashboard, specialists, new examination, and history. Source: `08-CONTEXT.md` D-12 and existing `frontend/app/(app)/operator/layout.tsx`.
- Admin sidebar must start at an explicit admin overview page and group system-management entries more densely than operator navigation. Source: `08-CONTEXT.md` D-13, D-16.
- Role-based landing stays explicit: `operator` lands in operator workstation, `admin` lands in admin overview, never in `/admin/users`. Source: `08-CONTEXT.md` D-14 to D-16.
- Reuse one shell primitive, but contour identity must differ through color balance, density, navigation labeling, and page-header treatment; different contours must not look like the same shell with different menu arrays. Source: `08-CONTEXT.md` D-01 to D-03.
- Focal point contract: on operator landing screens, the first-read anchor is the primary workflow/task surface; on admin landing screens, the first-read anchor is the overview/status surface that summarizes system state and management entry points.
- Visual hierarchy contract: page header -> primary task or overview surface -> supporting lists/cards -> secondary metadata and utilities. Executors should preserve this reading order across both contours.
- Default motion budget: `150ms` to `200ms` ease-out for hover, press, focus, sidebar item highlight, card elevation, and toast entry. No decorative looping animation. Source: `08-CONTEXT.md` D-08.
- Primary page and list loading states use skeletons, not centered generic spinners. Spinners remain acceptable for inline blocking actions only. Source: `08-CONTEXT.md` D-09.
- Shared UX primitives required in Phase 8 foundation: alert, toast, confirmation dialog, skeleton, empty state, inline field error, and semantic badge. Source: `08-CONTEXT.md` D-10.

## Component Inventory For Phase 8

- Shell: contour-aware `AppShell` refactor or split into shared structural primitive plus `OperatorShell` and `AdminShell` wrappers.
- Navigation: active item pill, section label, user session panel, logout confirmation.
- Page header: title, description, optional primary action, optional status badge.
- Surface primitives: card, panel, section divider, dark-shell container, empty state card.
- Form primitives: button, input, textarea, label, inline error, helper text, disabled state.
- Feedback primitives: alert, badge, skeleton, toast, confirmation dialog.

Do not introduce one-off page-specific styles before these shared primitives are normalized. Source: `08-CONTEXT.md` D-04, D-05 and `frontend/components/ui/*`.
