# Requirements: Мультимодальная система оценки психоэмоционального состояния специалистов

**Defined:** 2026-03-25
**Core Value:** Система должна давать оператору надёжный, интерпретируемый и воспроизводимый результат обследования специалиста, основанный на полном мультимодальном анализе речевых ответов, а не на ручной субъективной оценке.

## v1 Requirements

### Operator Entry and Navigation

- [ ] **OPUI-01**: Оператор видит минимальный экран входа с одной центрированной формой без информационных панелей, лишних описаний и декоративных блоков
- [ ] **OPUI-02**: Боковая навигация оператора остаётся структурно прежней, занимает всю высоту viewport и всегда держит кнопку выхода у нижнего края независимо от контента

### Operator Worklists

- [ ] **OPUI-03**: Главный экран оператора работает как search-first рабочая поверхность: заметный поиск специалиста, строка inline-статистики и один основной список недавних или активных специалистов без dashboard-карточек
- [ ] **OPUI-04**: Список специалистов отображается как плотный реестр или таблица с минимумом полей, где каждая строка сразу даёт открыть карточку специалиста
- [ ] **OPUI-05**: История обследований отображается как плоский журнал с фильтром сверху и строками, содержащими только специалиста, статус, время и действие открытия

### Operator Examination Flow

- [ ] **OPUI-06**: Экран обследования содержит только текущий вопрос, блок записи ответа и индикатор прогресса, без вторичных панелей, дублирующих статусов и поясняющих текстов
- [ ] **OPUI-07**: Все ключевые operator-экраны придерживаются workflow-first interaction model: списки и таблицы вместо карточек, один доминирующий action на экран и отсутствие текста, не влияющего на действие пользователя

## v2 Requirements

### Operator Productivity

- **OPFL-01**: Оператор может выполнять ключевые переходы по интерфейсу через keyboard shortcuts
- **OPFL-02**: Система поддерживает более глубокую очередь приоритетов обследований и навигацию по workload без открытия отдельных страниц

## Out of Scope

| Feature | Reason |
|---------|--------|
| Изменения административного интерфейса | Пользователь явно ограничил milestone только operator UX |
| Новые product features поверх существующего operator flow | Scope milestone — заменить interaction model, а не расширять функциональность |
| Изменение backend workflow, ML-логики или decision layer | Эти части не являются целью `v1.2 Operator UI` |
| Декоративный dashboard-style UI, карточные сетки и визуальные виджеты ради красоты | Прямо противоречит workflow-first принципу milestone |
